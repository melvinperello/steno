# Sprint 1: STENO Core Implementation

**Goal**: Build out the complete feature set of Steno as defined in `STENO_CLI_PLAN.md`. All core pillars (Zero SQLite, ~50MB RAM constant memory, dead-simple UX, Live Feedback) are in scope.

## Modules to Implement (in `src/steno/`)

1. **`hardware.py`**: Auto-detect NVIDIA GPU/VRAM and determine if CUDA `int8` or CPU `int8` fallback should be used.
2. **`preprocess.py`**: FFmpeg integration to convert input audio to 16kHz mono WAV format if it doesn't already exist. Includes the `wave.setpos()` chunking generator.
3. **`vad.py`**: Silero VAD (ONNX Runtime) integration to detect speech boundaries, padded by 64 samples. Output cached to `{name}.stvad.json`.
4. **`checkpoint.py`**: Pure JSONL file manager to append transcribed segments. Loads state immediately on resume.
5. **`transcribe.py`**: Core `faster-whisper` inference wrapper, emitting segments with confidence scores.
6. **`output.py`**: Formats the final `{name}.srt` and `{name}.csv`, filtering low-confidence tokens as `[UNCLEAR_AUDIO]`.
7. **`pipeline.py`**: The orchestration logic tying Preprocess -> VAD -> Transcribe -> Output together. Integrates `rich.live.Live` for the "Proof-of-Life" UI.
8. **`cli.py`**: The `click` entry point, handling single-file and directory batching (`steno ./folder`), and routing to the pipeline.

## Execution Steps

1. Scaffold utility modules: `hardware.py` and `checkpoint.py`.
2. Implement audio pipeline: `preprocess.py` and `vad.py`.
3. Implement ML inference: `transcribe.py` and `output.py`.
4. Tie it all together: `pipeline.py` and `cli.py`.
5. Write end-to-end testing instructions and verify memory constraints.

## Sprint 1 Retrospective

### 🏆 What Worked Beautifully (The Wins)
1. **The `wave.setpos()` Streaming Hack**: Converting the audio to a local WAV cache and seeking through it 10 seconds at a time kept our RAM footprint permanently pinned below 50MB, proving it scales infinitely without loading full files into memory.
2. **The VAD + Whisper Synergy**: Giving Whisper isolated 15-second blocks (generated by Silero) with `condition_on_previous_text=False` proved to be the ultimate sweet spot. It provides enough grammatical context for high accuracy, while completely neutralizing dead-air hallucinations.
3. **Bulletproof Resumability**: Relying on a pure `jsonl` file and manually invoking `os.fsync()` after every single sentence is incredibly lightweight and proved that SQLite is unnecessary for a robust, crash-proof pipeline.

### ⚠️ Pitfalls & Hard Lessons (The Challenges)
1. **The C++ Engine UI Freeze**: `faster-whisper` relies on the `CTranslate2` C++ engine, locking the Python thread while decoding (especially on a CPU). This made the terminal UI freeze. We had to inject a background `ui_ticker` thread to keep the timers and ETA calculating in real-time while the main thread was locked.
2. **False Positives in GPU Detection**: `onnxruntime` falsely reported CUDA availability just because the pip package was installed. We learned that the only bulletproof way to detect an NVIDIA GPU on Windows is to strictly poll the physical hardware via `subprocess.check_output(['nvidia-smi'])`.
3. **Rich Markup Clashing**: `rich`'s markup parser stripped our `[bold yellow]` colors because it confused literal brackets in our progress bar (e.g. `[00:15 / 00:30]`). We completely bypassed the string parser and explicitly applied styles to Python `Text` objects to guarantee UI rendering.
4. **The "Streaming" Illusion**: We initially assumed `faster-whisper` could yield text sentence-by-sentence natively. We learned that passing it a 15-second VAD clip forces it to process the whole clip atomically. We converted the python logic to a `yield` generator so the text hits the screen the exact millisecond the C++ engine releases the lock.
